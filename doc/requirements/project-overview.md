# 项目需求概述

## 一句话总结

将 CSDN 文章保存为本地 HTML、PDF 等文件，避免因网站停止运营而失去对优质内容的访问，并支持后续将这些文件上传到其他存储或平台长期保存。

## 项目背景

当前有许多网站因停止运营、服务调整或内容下线，导致其中的优质文章无法继续访问。项目希望将 CSDN 上有价值的文章转换并保存为本地文件，降低内容失效风险，并为后续迁移到其他存储位置或平台提供基础。

## 第一阶段范围

- 以 Web 服务形式提供功能。
- 首期支持通过单个 URL 保存一篇文章。
- 提交 URL 后采用同步下载，等待处理完成后返回成功或失败结果。
- 保存格式由用户选择，支持单选 HTML、单选 PDF，或同时选择 HTML 和 PDF，至少选择一种格式。
- 用户未特别指定时，默认保存 HTML。
- 文件先保存到本地，不接入外部上传平台。
- 同一 URL 重复保存时覆盖已有文件，只保留最新版本。
- 下载失败时显示具体失败原因，并提供重新下载功能。
- 单个图片或正文资源下载失败时，不导致整篇文章失败；保留已生成的文章文件，并提示缺失资源。
- 当同时选择 HTML 和 PDF 时，其中一种格式生成失败不影响另一种格式保存，并提示对应的失败原因。
- 第一阶段只支持无需登录即可公开访问的 CSDN 文章，不处理登录和付费文章。
- 作为本地小工具，第一阶段不设置额外的访问频率限制。
- 保存文章正文相关内容，包括正文文本、正文中的图片、代码和必要的排版信息。
- 只提取 CSDN 文章正文区域，不下载评论、推荐内容、广告、侧边栏等非正文内容。

## 本地文件规划

所有文章统一保存到项目根目录下的 `data/` 目录。

文件夹名称使用文章 URL 的域名，保证来源清晰。例如：

```text
data/
└── blog.csdn.net/
    └── <article-key>/
        ├── article.html        # 选择 HTML 时生成
        ├── article.pdf         # 选择 PDF 时生成
        ├── metadata.json
        └── assets/
            ├── image-001.png
            └── ...
```

其中：

- `blog.csdn.net/` 使用 URL 中的域名作为来源目录。
- `<article-key>/` 使用“文章 ID + 清理后的标题”命名；如果无法提取文章 ID，需要准备稳定的备用命名方案。
- `article.html` 保存可离线打开的正文 HTML。
- `article.pdf` 保存正文 PDF。
- `metadata.json` 保存原始 URL、标题、作者、发布时间、标签、保存时间等可检索信息。
- `assets/` 保存正文引用的图片等本地资源，HTML 使用相对路径引用；不下载非正文区域的资源。

## 本地搜索规划

Web 服务只提供一个简单的本地文章检索入口，不额外提供文章列表首页。使用一个关键词输入框，对以下信息进行模糊匹配：

- 文章标题
- 来源域名
- 原始 URL
- 作者和标签（如果页面能够可靠提取）

搜索结果应能定位到文章目录，并打开本地 HTML 或 PDF 文件。首期只搜索标题、来源域名、原始 URL、作者和标签等元数据，使用本地元数据建立轻量索引，避免每次搜索都遍历所有文件；正文全文搜索作为后续扩展。

搜索结果只展示文章标题和地址；如果生成了 HTML，地址指向本地 HTML 文件，否则指向本地 PDF 文件。
