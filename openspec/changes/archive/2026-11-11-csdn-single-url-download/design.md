## Context

仓库提供一个本地 FastAPI Web 服务，负责抓取公开 CSDN 页面、提取正文、下载正文资源、生成 HTML/PDF、保存文件并建立 SQLite 元数据索引。本设计整合首期实现过程中形成的最终方案，作为项目唯一首期需求的技术记录。

## Goals / Non-Goals

**Goals:**

- 用一个同步的本地单体服务完成单篇文章归档。
- 生成可离线打开的正文 HTML，并按需生成 PDF。
- 使用文件系统保存内容、SQLite 保存检索元数据。
- 对单个资源和单个格式失败提供部分成功结果。
- 保留代码内容和视觉格式，并提供默认折叠及打印可见能力。

**Non-Goals:**

- 不实现批量导入、后台任务队列、用户账号或登录态。
- 不处理登录文章、付费文章或正文全文搜索。
- 不接入外部对象存储或上传平台。

## Decisions

### 1. Python 单体 Web 服务

使用 Python 3.12、FastAPI、服务端模板、BeautifulSoup/lxml、Playwright 和 SQLite。该组合能在一个进程内完成 Web 交互、解析、渲染和本地索引，适合开源的小型本地工具。

### 2. 统一归档流水线

请求按 URL 校验、公开范围判断、页面抓取、元数据提取、正文清理、资源下载、HTML/PDF 生成、暂存目录提交和索引更新的顺序执行。只要至少一个用户选择的输出可用，就提交本次结果；资源或另一格式失败则保留成功产物并返回警告。

### 3. 文件系统保存内容，SQLite 保存索引

文章保存为 `data/<domain>/<article-key>/`，包括 `article.html`、可选 `article.pdf`、`metadata.json` 和 `assets/`。SQLite 记录标题、域名、原始 URL、作者、标签、保存时间和可用格式，用于搜索及已下载文件列表。

### 4. 正文模型同时驱动 HTML 和 PDF

先生成只包含正文的规范化 HTML，再同时用于离线 HTML 输出和 Playwright PDF 打印。正文清理采用明确的非正文容器选择器，避免误删 `span.token.comment` 等代码语法节点；代码块保留文本、换行、空白和边框字符，HTML 使用深色样式和 `details/summary` 折叠，打印样式强制显示代码。

### 5. 兼容公开页面访问并限制文件路由

页面抓取使用浏览器风格请求头和兼容性更好的标准库 HTTPS 连接，跟随有限重定向，将网络异常转换为用户可读错误。仅识别明确登录限制；本地文件通过受控路由访问，禁止任意路径和暂存目录。

### 6. 首页列表和搜索共用索引结果

无关键词时从 SQLite 按 `saved_at DESC` 获取全部归档，有关键词时执行标题、域名、URL、作者和标签模糊匹配。两者共用 HTML 优先、PDF 回退和本地 URL 转换逻辑。

## Risks / Trade-offs

- 页面结构变化 → 集中维护正文选择器，并用真实页面样本做回归测试。
- 资源受防盗链或网络波动影响 → 资源逐项下载并记录失败，不丢弃整篇文章。
- PDF 浏览器体积较大 → 将 Playwright Chromium 安装作为明确的本地开发步骤。
- 同步请求耗时较长 → 第一阶段保持同步模型，后续批量需求再引入后台任务。

## Migration Plan

首期没有旧应用数据，启动时创建 `data/` 和 SQLite 索引。未来版本继续以 `data/<domain>/<article-key>/` 为可迁移单元，不需要改变归档文件布局。
