## Context

现有首页只在提交关键词后调用索引搜索，空关键词时不会读取任何记录，因此用户无法直接浏览已下载文章。SQLite 的 `articles` 表已经保存了标题、归档目录、格式和保存时间，文件地址生成逻辑也已由首页复用；本变更只需要扩展查询和首页展示。

## Goals / Non-Goals

**Goals:**

- 让首页无关键词时展示全部可用的本地文章归档。
- 让关键词搜索和文件列表使用同一份结果数据和 HTML/PDF 回退规则。
- 保证列表按 `saved_at` 从新到旧排序，并对没有记录的情况给出明确提示。
- 不改变已有下载、覆盖保存和本地文件安全校验逻辑。

**Non-Goals:**

- 不新增独立的文件管理 API、分页、批量删除或重新排序功能。
- 不扫描 `data/` 目录中的未进入 SQLite 索引的文件。
- 不增加新的数据库表、依赖或正文全文索引。

## Decisions

### 1. 在现有索引层增加“全部列表”查询

在 `ArticleIndex` 中增加无关键词的列表查询，复用现有结果转换和文件选择逻辑，SQL 按 `saved_at DESC` 排序。虽然空关键词搜索可以通过 `LIKE %%` 得到全部结果，但显式的列表查询能表达不同用途，也避免将搜索语义与首页浏览耦合。

备选方案是直接遍历 `data/` 目录；该方案无法可靠获取保存时间和标题，也可能展示未完成或未登记的文件，因此不采用。

### 2. 首页统一渲染列表

首页路由始终准备一个 `results` 集合：有关键词时调用现有模糊搜索，无关键词时调用全部列表查询。模板保留现有搜索表单，使用同一个列表组件展示结果；有关键词时显示“搜索结果”，无关键词时显示“已下载文件”。

### 3. 继续沿用受控本地地址

索引结果仍只返回标题和归档文件路径，首页继续通过 `_file_url` 转换为 `/files/...` 地址。HTML 优先、PDF 回退仍由索引层根据实际文件存在情况决定，模板不接触原始 URL 或文件系统路径。

### 4. 使用明确的空状态

当无关键词且没有归档时显示“暂无已下载文件”；搜索无结果时继续显示现有的“没有找到匹配的文章”。这样可以区分首次使用和搜索失败两种状态。

## Risks / Trade-offs

- [列表数据量增长] → 第一阶段按现有 SQLite 索引一次性读取，保持实现简单；后续数据量明显增加时再引入分页。
- [索引记录对应文件已被手动删除] → 复用现有逻辑，将地址置为空；模板应跳过不可打开的记录或以不可用状态处理，不能暴露文件系统路径。
- [保存时间格式不一致] → 继续使用归档时写入的 ISO 时间字符串，并保持现有排序约定。

## Migration Plan

不需要数据库迁移。升级后首页直接读取现有 `articles` 表，历史归档会自动出现在列表中；回滚时只需恢复首页路由、模板和索引查询的代码版本。
