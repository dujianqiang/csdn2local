## Context

当前项目由 FastAPI + Jinja2 提供 5 个独立页面：单篇下载、单篇结果、专题下载、专题进度和专题结果。页面目前主要依赖浏览器默认样式；后端字段、路由和异步专题任务已经稳定，本次设计应集中在模板和共享静态样式，避免引入新的前端框架或改变下载行为。

## Goals / Non-Goals

**Goals:**

- 建立一个可复用的“本地文章档案馆”视觉语言，服务于保存、检索和确认任务结果。
- 让首屏立即说明产品用途，并把 URL 输入和主要动作放在视觉中心。
- 让进度、成功、部分成功和失败状态在视觉上有明显差异，同时保持语义清晰。
- 在桌面和窄屏设备上保持表单、导航和输出链接可用。
- 让页面只使用项目内共享 CSS，不增加运行时依赖。

**Non-Goals:**

- 不改动抓取、归档、专题任务、文件访问或输出格式逻辑。
- 不新增登录、批量导入、全文搜索或前端单页应用。
- 不把所有内容拆成统一圆角卡片；内容层级通过留白、分隔线、底色和排版区分。

## Decisions

### 视觉方向：本地知识档案馆

将产品定位为“把会消失的网页，保存成自己的阅读档案”。页面以深墨蓝作为工作台底色，以骨白文字和珊瑚橙行动色建立强对比；文章列表像档案索引，专题进度像装订前的处理台。这样把颜色和结构绑定到“本地保存”主题，而不是使用通用 SaaS 卡片或渐变装饰。

### Token system

- `--ink: #111a2b`：工作台主背景。
- `--ink-soft: #1c2940`：表面层和导航区域。
- `--paper: #f4efe6`：主要阅读背景与高对比内容层。
- `--muted: #a9b4c5`：次要说明文字。
- `--coral: #f06b4f`：唯一主行动色、进度强调和当前状态。
- `--mint: #8ed4bd`：成功状态；`--amber: #f4bf68` 用于部分成功或警告。

### Typography

标题使用 `Noto Serif SC` / `Source Han Serif SC` 等系统可用的中文衬线字体，形成“编辑室/档案”的气质；正文和控件使用 `Noto Sans SC` / `Microsoft YaHei UI` 等无衬线字体，保证表单可读性。标题使用 sentence case 风格，不使用全大写眉标或单词变色作为装饰。

### Layout

桌面端采用 12 列的非对称工作台：左侧是品牌叙事和功能导航，右侧是主要任务表单；本地文章列表跨越主体区域，以横向索引行呈现。单篇页的首屏重点是输入 URL 的“保存台”，专题页在同一位置替换为任务配置。

```text
┌──────────────────────────────────────────────────────────────┐
│  csdn2local                         单篇下载  专题下载        │
├───────────────┬──────────────────────────────────────────────┤
│  LOCAL         │  把网页，保存成自己的阅读档案                 │
│  ARCHIVE       │  一句说明 · 当前任务的实际收益                 │
│               │                                  ┌───────────┐ │
│  功能入口      │  已下载文章 / 专题配置          │ URL 输入  │ │
│  当前状态      │                                  │ 格式选择  │ │
│               │  本地档案索引                    │ 主按钮    │ │
└───────────────┴──────────────────────────────────┴───────────┘
```

内容默认左对齐，标题和表单标签保持短行宽；只在状态徽章、进度条和主要按钮上使用强调色。窄屏时将左侧说明移到顶部，表单和结果列表变为单列，不隐藏核心操作。

### Shared template shell

新增 `base.html` 作为共享骨架，页面通过 `active_nav`、`page_title` 和可选的 `body_class` 注入差异。共享 CSS 放在 `app/static/styles.css`，由 FastAPI 挂载 `/static`。现有表单 action、字段名、模板上下文变量和文件链接保持原样。

### State presentation

使用语义类名表达状态：`is-success`、`is-warning`、`is-error`、`is-progress`。状态区域包含简短标题、说明、主要动作和次要动作；不使用只靠颜色表达差异的提示。进度页保留现有 2 秒刷新机制，只把阶段、数量和耗时重新排版。

### Motion and accessibility

只给首屏主工作台做一次轻微的加载显现；列表和卡片不做逐项上浮动画。CSS 提供 `:focus-visible` 高亮和 `@media (prefers-reduced-motion: reduce)` 覆盖。链接、按钮和表单控件维持足够对比度与触控尺寸。

## Risks / Trade-offs

- [风险] 本机未安装指定字体 → [缓解] 使用中文系统字体回退栈，不依赖外部字体下载。
- [风险] 共享模板引入后现有页面上下文变量遗漏 → [缓解] 逐页保留现有变量名，并运行现有 Web 测试覆盖成功、失败和进度页面。
- [风险] 深色背景降低长列表阅读舒适度 → [缓解] 文章索引使用纸张色内容层，并限制每行信息密度。
- [风险] 独立模板仍可能出现局部样式覆盖 → [缓解] 统一使用带页面前缀的组件类名，避免宽泛的 `.section`、`.card` 等选择器。

## Migration Plan

1. 增加静态资源挂载和共享模板骨架。
2. 逐页迁移现有模板，保持路由与字段契约不变。
3. 运行测试并启动本地服务，检查桌面和窄屏截图。
4. 如需回滚，只需恢复模板、静态资源和静态挂载改动，不涉及数据迁移。
