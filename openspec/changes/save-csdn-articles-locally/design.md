## Context

仓库目前只有项目文档和 OpenSpec 配置，没有既有应用架构或运行时约束。实现需要覆盖同步 Web 请求、CSDN 页面解析、正文资源下载、可选 HTML/PDF 输出、本地文件保存和元数据搜索；详细行为以 `proposal.md` 及两份 capability spec 为准。

## Goals / Non-Goals

**Goals:**

- 用一个本地单体 Web 服务完成提交、下载、归档和搜索。
- 让生成的 HTML 在没有网络的情况下仍能使用正文本地资源打开。
- 通过统一的中间文章模型复用 HTML 和 PDF 生成流程。
- 通过文件系统保存归档，通过 SQLite 保存搜索所需的元数据索引。
- 以可报告的部分成功结果容纳单个资源或单个输出格式失败。

**Non-Goals:**

- 不引入后台任务队列、用户账号、登录态或外部对象存储。
- 不实现正文全文搜索、批量导入、CSDN 登录文章或付费文章处理。
- 不保留同一 URL 的历史版本。

## Decisions

### 1. 采用 Python 单体 Web 服务

使用 Python 3.12、FastAPI 和服务端模板构建本地 Web 服务；使用 `httpx` 获取页面和资源，使用 BeautifulSoup/lxml 解析正文，使用 Playwright 生成 PDF，使用 SQLite 保存索引。

选择该组合是因为它能在一个进程内覆盖 HTTP 服务、HTML 解析和浏览器渲染，适合本地小工具；相比拆分前后端或引入独立任务服务，部署和调试成本更低。Node.js 全栈方案也可行，但当前没有既有 Node 工程基础，暂不引入额外前端构建链。

### 2. 使用统一的归档流水线

一次同步请求按以下阶段处理：

1. 校验 URL、确认公开访问范围并抓取页面。
2. 从页面中提取文章标题、文章 ID、元数据和正文根节点。
3. 清理正文中的非正文节点，收集正文引用的资源。
4. 将资源下载到暂存目录的 `assets/`，把 HTML 引用改写为相对路径。
5. 按用户选择生成 HTML 和/或 PDF。
6. 写入 `metadata.json`，更新 SQLite 索引并提交归档目录。

所有步骤先写入带唯一标识的暂存目录。只要至少有一个用户选择的输出可用，就提交该次最新结果；资源或另一种格式失败则作为警告返回。若没有任何可用输出，则不替换现有归档。

### 3. 文件系统是内容事实来源，SQLite 只做搜索索引

文章内容按以下结构保存：

```text
data/
└── <domain>/
    └── <article-id>_<sanitized-title>/
        ├── article.html       # 若选择 HTML
        ├── article.pdf        # 若选择 PDF
        ├── metadata.json
        └── assets/
```

SQLite 数据库保存文章目录、标题、域名、原始 URL、作者、发布时间、标签和可用输出格式。搜索只对这些字段做大小写不敏感的模糊匹配，不建立正文全文索引。覆盖保存时先完成新归档，再在索引事务中替换同 URL 的旧记录。

### 4. HTML 与 PDF 使用同一份清洗后的正文模型

先生成只包含正文的规范化 HTML，再以它作为 HTML 输出和 PDF 渲染输入。HTML 输出通过本地相对路径引用 `assets/`；PDF 使用 Playwright 加载暂存中的本地 HTML 后打印为 PDF。这样可以避免 PDF 与 HTML 分别解析页面而产生内容差异。

### 5. 只暴露受控的本地文件地址

搜索结果只返回文章标题和由服务生成的本地文件链接。服务根据归档元数据优先链接 HTML，HTML 不存在时链接 PDF，不直接把任意用户提交的文件系统路径暴露给浏览器。

### 6. 同步请求不引入任务队列

下载请求在一个 HTTP 请求中完成，页面显示处理中、成功、部分成功或失败结果；失败结果包含可读原因和用于重新提交相同 URL/格式的重试入口。第一阶段不设置额外访问频率限制。

## Risks / Trade-offs

- **CSDN 页面结构变化** → 将正文选择器和正文识别逻辑集中封装，并保留解析失败的明确错误；用真实页面样本补充回归测试。
- **正文资源受防盗链或网络波动影响** → 资源逐项下载、记录失败清单，不因单个资源失败丢弃整篇文章。
- **PDF 浏览器运行时体积较大** → 将 Playwright 浏览器作为明确的本地安装依赖，并在启动检查中给出缺失提示。
- **同步请求耗时较长** → 第一阶段接受同步模型，设置合理的请求超时并返回阶段性错误；后续如需大批量处理再引入后台任务。
- **标题包含 Windows 文件名非法字符或过长** → 使用统一的标题清理、长度限制和稳定回退命名，原始标题保存在元数据中。
- **覆盖保存过程中出现中断** → 先在暂存目录完成生成并校验至少一个输出，再执行目录替换和索引更新，避免留下半成品作为最新版本。

## Migration Plan

当前没有既有应用或归档数据。首次启动时创建 `data/`、SQLite 索引和必要的运行目录；部署失败时可停止服务并删除本次新建的运行文件，已有文章目录不需要迁移。未来上传到外部平台时，以 `data/<domain>/<article-key>/` 作为可迁移单元。

## Open Questions

- 文章 ID 无法提取时的稳定备用命名规则可在实现前根据 CSDN URL 样本确定。
- CSDN 正文选择器需要通过实际公开文章样本验证，必要时再调整解析规则。
- 版权提示和使用边界需要在 Web 页面文案中补充，但不改变当前归档数据结构。
