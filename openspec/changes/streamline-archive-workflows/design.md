## Context

保留现有 FastAPI、Jinja 页面、后台专题任务与本地归档结构。单篇仍经原表单提交，专题继续重定向到独立任务地址。

## Goals / Non-Goals

为第一次使用和回看本地内容提供同等清晰的入口。改动集中在 Web 交互与安装包。

## Decisions

- 单篇、专题、进度及结果共用 Jinja 模板外壳与本地样式。使用浅灰蓝底、白色工作区、深蓝文字、蓝色主操作和琥珀色提醒。桌面和手机均先展示任务表单，再展示记录。控件保留键盘焦点，动态效果遵循系统设置。
- 品牌左对齐，功能导航右对齐，宽度不足时导航整组换到下一行并保持右对齐。两个等宽入口共用浅蓝灰底，当前项以白底、蓝色文字和细描边标记。导航保留「单篇下载」和「专题下载」两个短标签，下载范围由各页标题和说明介绍。每个入口至少高 44 像素，整块可点击，支持键盘切换。实心蓝色用于表单提交按钮。
- 两种下载表单都先展示地址和输出选项。专题并发和另存 HTML 属于高级设置。错误时展开高级设置并保留输入，编辑结果中的地址可带回原参数。
- 提交反馈使用少量原生 JavaScript，并通过页面恢复事件恢复提交按钮。专题通过只读状态端点更新局部进度，结束时进入原任务结果地址。关闭 JavaScript 时继续用页面刷新显示进度。
- 活动任务入口由现有任务队列提供。离线输出和下载记录沿用现有路由。
- 两页共用原生文件类型下拉框和控件样式，通过 GET 参数 `history_format` 保留筛选状态。空值和未知格式按全部类型处理。选择变更时脚本提交当前表单，锚点将视图带回下载记录。关闭脚本时可手动提交，窄屏时记录标题与筛选表单可分行。
- 单篇先按关键词搜索，再按实际文件筛选。标题链接随所选格式更新，清除关键词时保留格式。专题先筛选有效的磁盘归档，再按专题归组，由最新匹配版本决定标题链接和排序。各版本按保存时间降序逐行显示格式、篇数和保存时间，链接至对应详情。现有和旧归档均使用同一筛选流程。

## Risks / Trade-offs

- [连接暂时断开] → 专题进度保留最近状态，提供手动刷新，后续轮询继续检查。
- [安装包遗漏前端文件] → 在包清单中包含 CSS 和 JavaScript，并验证安装包内容。

## Migration Plan

替换模板和静态文件即可加载新版。已有归档按原路径访问，无需数据迁移。
