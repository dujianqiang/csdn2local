## Context

专题下载复用单篇 CSDN 文章的抓取、正文清理、资源下载、本地存储和受控文件访问能力，在同一流程上增加专题页面解析、顺序编排和统一输出。

## Goals / Non-Goals

**Goals:**

- 从一个公开专题地址解析出有序的文章列表。
- 支持可配置并行数量，默认并行数量为 1；在提高并行度后仍按专题原始顺序编排结果。
- 将成功文章合并为一个带目录的 HTML、EPUB、PDF 或 Markdown 文件，每次选择一种格式。
- 复用单篇正文和资源处理逻辑，避免专题和单篇产生不同的正文结果。
- 在前端提供单篇下载和专题下载两个清晰的功能入口。

**Non-Goals:**

- 第一版同一时间处理一个专题，专题内部允许有限并发下载。任务状态保存在当前服务进程中。
- 不把专题输出拆成多个用户可选的最终文件；每次专题任务只提交一种输出格式。
- 保留单篇文章已有的保存格式和本地搜索语义。

## Decisions

### 1. 顺序解析和可配置并发处理

专题解析器从专题页面提取文章链接，按页面出现顺序建立有序列表，并对规范化后重复的 URL 去重但保留首次位置。专题任务使用有界并发执行单篇下载，默认并发数为 1，用户可以通过专题表单调整为有效的正整数。每个任务携带原始序号，结果收集后按序号排序再生成导航和最终输出。

对于 CSDN `category_*.html` 专栏，标题取自专栏标题区域，链接只从「专栏收录文章」列表提取。找不到该列表时报告无可识别文章，避免将侧栏推荐和最新评论误计入专题。

并发数量由服务端校验并限制为正整数；并发只影响下载执行速度，不改变文章顺序。默认值设为 1，便于保持与单篇下载相同的网络压力和调试行为。

按专题顺序以并行数量为每批的最大篇数。每批全部结束后等待 1 秒，再提交下一批。最后一批结束后直接处理导出。

### 2. 复用单篇文章处理流水线

专题任务只负责专题页面抓取、文章顺序、失败记录和最终编排；每篇文章的正文提取、资源下载、代码格式保留和错误转换继续复用现有服务。专题编排接收每篇文章的规范化正文模型，而不是重新抓取或解析已保存 HTML。

这样可以保证专题输出和单篇下载遵循相同的正文范围、代码样式和资源处理规则。

单篇和专题共同调用 `ArchiveService.prepare_article`，传入各自的资源目录，取得元数据、正文和警告。专题复用归档暂存、提交和清理方法，只把合并后的专题输出保存到专题目录。

专题首页与文章页面共用 `PageFetcher`。遇到 TLS EOF、连接重置或正文读取不完整时，丢弃本次响应并从原地址重新请求，最多重试两次，间隔 2 秒和 5 秒。普通 HTTP 521 沿用原有重试间隔。明确的安全防护拦截、证书验证错误及其他 HTTP 错误沿用现有处理。重试耗尽后报告具体原因及尝试次数。

失败行可以导入对应文章的浏览器另存 HTML。导入使用同一条逐篇恢复流程，从已有归档读取成功文章，在暂存目录合并后一次性提交，不重新请求专题目录和成功文章页面。

Windows 拒绝移动目录时，对访问拒绝、共享冲突和锁冲突做短暂重试。原归档已移至备份而暂存目录仍无法移动时，先将产物复制到目标父目录下的隐藏目录，再发布这份完整副本。若无法完成发布，尝试恢复原归档。恢复失败时保留备份并报告位置。

### 3. 单选输出格式

专题表单使用单选控件，格式枚举为 `html`、`epub`、`pdf`、`md`，默认 HTML。HTML 生成合并文档，EPUB 生成 EPUB 3 文件，PDF 使用合并后的离线 HTML 打印生成。Markdown 使用本地化正文生成 UTF-8 文档，保留按序排列的目录、相对图片路径和失败原因。

专题结果页和历史记录复用单篇 Markdown 下载包，将 `topic.md` 和当前归档的 `assets/` 打包。逐篇补档后重新下载可取得更新的正文和资源。

专题文件使用提交的栏目或专题地址，以及专题目录中记录的逐篇 URL。沿用归档 URL 规范化规则，保留查询参数。HTML 在标题下显示可点击的地址，PDF 和 EPUB 复用相同的正文标注，Markdown 生成完整的链接。失败条目也显示原文地址。读取旧 HTML 或 EPUB 正文用于补档时，先去除已有的归档来源标注，再统一生成一次。历史文件可按需重新下载或补档。

选择多种格式时返回参数错误，不隐式生成额外文件，避免用户误以为专题输出是多选任务。

### 4. 统一的专题导航模型

编排器先生成一个有序导航模型，包含专题标题、文章标题、顺序编号、成功状态和内部目标地址。HTML 使用文档内锚点，EPUB 使用 `nav.xhtml` 和章节内部链接，PDF 在首页生成可点击的目录/导航区域并按顺序插入文章内容。

单篇失败的文章仍保留在导航模型的原始位置，但以失败状态显示原因且不生成不可打开的链接；成功文章的导航地址全部指向专题输出内的本地内容，不再依赖 CSDN 在线地址。

专题结果页和历史详情共用文章列表。HTML 链接使用 `#article-N` 跳到本地正文，PDF 链接使用 `#nameddest=article-N` 跳到本地 PDF 中的对应位置。两者按原始序号定位，复用已有产物的目录目标。EPUB 和 Markdown 的标题链接打开同一归档目录下的单篇本地阅读视图，复用已归档正文和同级 `assets/`。缺少正文缓存的旧 EPUB 从书内读取正文。失败文章保留「打开原文」入口。

### 5. 专题文件布局和提交

专题归档使用独立目录，例如：

```text
data/
└── topics/
    └── <topic-key>/
        └── <前N篇或全部>/
          └── <format>/
            ├── topic.html / topic.epub / topic.pdf / topic.md
            ├── metadata.json
            └── assets/
```

输出先写入暂存目录，只有在至少有一篇文章成功且最终单一输出生成成功后才提交专题目录和元数据。失败文章、原始专题地址、文章顺序、选定格式和警告写入 `metadata.json`。

### 6. 前端采用独立页面和共享导航

`/` 提供单篇下载，`/topic` 提供专题下载。专题表单接收地址、篇数、单选格式与并行数量。并行数量默认 1，非法值在提交时给出明确提示。共享导航与页面反馈见[样式优化](../streamline-archive-workflows/design.md)。

### 7. 专题任务进度

提交专题后，将任务交给本地后台线程并重定向到任务自己的进度地址。服务在内存中保存最近任务的状态。已有任务执行时，新的提交提示当前任务正在运行并提供进度链接。页面每两秒刷新一次，显示读取专题、下载文章、生成输出三个阶段和实际耗时，完成后在同一地址显示结果。

任务失败或部分成功时，结果页允许使用原专题地址、格式和并行数重新下载。

专题服务通过回调报告总数和已处理篇数。并行任务按实际完成的时间更新成功和失败计数，最终输出仍按原始序号排列。服务重启后，进度地址提示返回专题下载入口，已经生成的文件仍保存在原来的位置。

专题下载页在表单下方列出已提交到磁盘的专题归档。每条记录使用同目录的 `metadata.json` 获取标题和格式，使用实际输出文件的修改时间排序。试下载记录以现有目录命名或元数据识别。标题链接进入专题详情，可打开已保存的版本。缺少产物或元数据无效的目录不显示。

### 8. 验收期间限制下载篇数

专题表单默认处理去重后的前五篇文章，保持专题原始顺序。用户可以为每次任务填写任意非负整数，填 0 表示全量下载。启动配置 `CSDN2LOCAL_TOPIC_ARTICLE_LIMIT` 可覆盖表单默认值。进度和结果会标明限量范围。

### 9. 使用浏览器另存的文章 HTML

用户能在浏览器正常查看文章时，可将文章另存为「网页，仅 HTML」，用文章 ID 命名并在专题表单或结果页选中文件。服务在后台任务中按本次专题目录和文章 ID 校验文件。匹配到本地文件的文章直接使用文件正文，其余文章沿用在线下载。文件通过共享的正文清理和资源处理流程，来源记录在专题元数据中。失败结果保留每篇文章的原文链接。

### 10. 文章请求使用真实导航上下文

验收实际专题时发现，旧抓取器固定发送过期的 `Chrome/131` User-Agent，且专题文章请求没有携带从专题目录跳转而来的导航上下文，导致目录可以读取但文章连续返回 HTTP 521。问题不是继续增加相同请求的重试次数可以解决的。

共享抓取器改为发送可配置的现代 Chrome User-Agent、文档导航相关的 `Sec-Fetch-*` 请求头和缓存控制头。专题文章请求额外携带专题地址作为 `Referer`，并标记为同源文档导航；单篇入口没有上游页面时不伪造 Referer。User-Agent 支持通过 `CSDN2LOCAL_USER_AGENT` 覆盖，便于本机浏览器版本变化时调整。

该调整不绕过登录、付费或安全验证，也不改变 HTTP 521 的错误边界；它只让程序的标准 HTTP 请求与用户从专题目录打开文章时的请求上下文保持一致。若站点仍拒绝请求，结果页继续提供逐篇原文链接和浏览器另存 HTML 的补充入口。

### 11. 专题详情与逐篇重试

专题列表按专题标识合并，在标题下列出每份已保存归档的格式和篇数范围，链接进入对应版本的详情。新产物目录包含格式和篇数上限，切换格式或篇数不会覆盖其他版本，旧目录仍可打开。

篇数是专题表单的任务参数，启动配置提供默认值（默认 5）。0 表示处理全部已发现的文章，编辑和重试保留本次值。

逐篇重试使用原任务或已保存产物的文章顺序，只请求选中的失败文章。新产物额外保存可重编排的正文；旧 HTML 和 EPUB 从归档还原正文，旧 PDF 缺少正文源时提供整专题重新下载。重新生成成功后原子替换产物。失败时保留先前产物。全部失败的任务可从原进度结果页继续重试。

## Risks / Trade-offs

- [专题页面结构变化] → 将专题链接选择器集中封装，保留规范化 URL 去重，并用多个专题页面样本建立解析测试。
- [专题文章数量较多，下载等待时间较长] → 在后台执行，并持续显示阶段、文章计数和耗时。
- [并发过高造成网络压力或触发站点限制] → 默认并行数为 1，服务端校验正整数并保留用户可调但有界的配置入口。
- [单篇失败造成专题内容不完整] → 继续处理后续文章，在导航原顺序位置展示失败状态和原因。
- [EPUB 目录或资源引用不规范] → 使用固定的 EPUB 3 包结构、`nav.xhtml` 和本地资源路径，并增加解包结构测试。
- [PDF 导航交互受渲染器限制] → 先保证首页目录和文章顺序可见，并使用离线 HTML 内部链接生成可点击导航。

## Migration Plan

旧归档按专题标识、篇数和格式迁移。同规格的重复旧版本保留在详情中。迁移命令和旧链接映射见[单个网页下载](../download-single-page/design.md)。
