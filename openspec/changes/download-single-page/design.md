## Context

单篇归档由本机 FastAPI 服务同步处理。栏目下载复用单篇的正文和资源处理流程，专题编排见[栏目批量下载](../download-csdn-topic/design.md)。

## Goals / Non-Goals

提供公开文章的离线文件、本地检索及历史归档迁移。检索范围为文章元数据。

## Decisions

- 校验 URL 后获取正文和元数据，下载正文资源到 `assets/`。HTML 使用本地相对路径，代码块默认可折叠且打印时展开。
- 单篇与专题共用页面抓取器。可恢复的连接断开、正文读取不完整或普通 HTTP 521 每次等待 1 秒后重试，最多重试两次。明确的安全防护拦截立即报告。
- 单篇网页表单使用单选按钮，默认 HTML。网页请求只接受一个格式，失败后可按原参数重试。PDF 渲染使用的临时 HTML 随任务清理。保留归档服务的批量格式参数兼容内部调用。
- 文档标题下显示用户提交的文章 URL，按归档规则规范化域名并移除页内锚点，保留查询参数。重定向后的地址用于解析正文和相对资源。PDF 沿用 HTML 的来源标注，Markdown 生成可点击的完整地址。历史文件可按需重新下载。
- Markdown 的网页下载入口从现有归档按需打包 `article.md` 和 `assets/`。文档与资源保留原目录关系，直接访问 Markdown 文件的旧链接仍可使用。
- 单篇和专题 HTML 共用代码块打印样式，打印时显示折叠内容，并允许代码长行在页宽内换行。Playwright 在打印页展开代码块并加载同一份样式，使较早归档的 HTML 也可重新导出 PDF。
- 单篇和专题共用 PDF 渲染入口。Playwright 报告浏览器缺失时，通过当前 Python 的 Playwright CLI 安装匹配的 Chromium Headless Shell，再继续导出。进程内串行准备运行时，复用同一浏览器缓存。自动安装仅下载浏览器，Linux 系统库由用户按错误提示补装。
- 单篇写入 `data/articles/<文章目录>/`，目录按文章 ID 和标题生成。发布前，将同一文章其他格式及其资源复制到暂存目录，沿用原子替换流程。同格式成功下载时更新该格式。资源文件名包含内容摘要，使已保存文档和新文档可分别引用同一 URL 的不同图片内容。
- 在进程内串行合并、发布及更新索引，使并行保存同一篇文章的请求保留彼此的产物。元数据记录全部可用格式，下载列表按磁盘上实际存在的文件生成链接，兼容旧索引和旧归档。
- 应用启动时初始化 `data/.internal/index.sqlite3`，兼容旧位置 `data/index.sqlite3`。Git 忽略 `data/`，并在仓库各层级按名称忽略 `index.sqlite3`、`index.sqlite`、`index.sqllite` 及其 WAL、SHM 和回滚日志。
- 文件路由限制到归档目录。迁移命令默认只预览，执行时核对目标文件并记录旧路径映射，原件存入 `data/.internal/legacy/`。

## Risks / Trade-offs

- 页面结构变化时通过解析样本复测正文提取。
- PDF 生成依赖 Playwright Chromium。首次下载失败时保留重试入口，手动安装步骤见 [README](../../../README.md#启用-pdf)。
- 原始 URL 可能包含查询参数或括号，按各格式转义文本和链接，并验证 PDF 中显示的文本及链接目标。
- 迁移时停止本地服务，避免正在写入的归档与迁移同时发生。
