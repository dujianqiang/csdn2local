## Purpose

通过一个公开的 CSDN 文章链接保存正文、代码和必要资源，并提供离线阅读、检索及旧归档迁移。

## ADDED Requirements

### Requirement: 保存和检索单篇文章

系统 SHALL 同步归档一篇公开的 CSDN 文章，网页每次保存一种格式及必要资源，并按本地元数据检索已保存文章。支持 HTML、PDF 和 Markdown。

#### Scenario: 使用默认格式保存单篇文章

- **WHEN** 用户提交一个无需登录即可访问的 CSDN 文章 URL，且未明确选择格式
- **THEN** 系统同步处理请求，默认生成 HTML，并将文章保存到本地

#### Scenario: 保存用户选择的格式

- **WHEN** 用户提交一个公开 CSDN 文章 URL，并选择一种格式
- **THEN** 系统同步处理请求，仅生成用户选择的格式；同时提交多个格式时返回参数错误

#### Scenario: 拒绝不支持的访问范围

- **WHEN** 文章需要登录、付费或其他受限访问权限
- **THEN** 系统报告明确失败原因，不将请求视为成功归档

#### Scenario: 重试临时页面请求失败

- **WHEN** 页面请求遇到 TLS EOF、连接重置、正文未完整接收或普通 HTTP 521
- **THEN** 系统每次等待 1 秒后重试，最多重试两次。明确的安全防护拦截立即报告。

#### Scenario: 只提取文章正文

- **WHEN** 页面同时包含文章正文、评论、广告、推荐、侧边栏或其他页面外壳
- **THEN** 归档文件只包含文章标题、正文和正文所需资源，不保存非正文内容

#### Scenario: 保存正文资源到本地

- **WHEN** 正文引用图片或其他必要资源
- **THEN** 系统将资源保存到文章目录的 `assets/` 下，并让离线 HTML 和 Markdown 使用本地相对地址

#### Scenario: 保留代码内容和视觉格式

- **WHEN** 正文代码包含注释、换行、缩进、空白或 ASCII/Unicode 边框字符
- **THEN** 归档 HTML 保留这些内容和有意义的排版；代码块使用深色样式，默认折叠且可以展开

#### Scenario: 打印和 PDF 保持代码可见

- **WHEN** 用户打印归档 HTML 或选择生成 PDF
- **THEN** 打印内容包含折叠代码块，超出页面宽度的代码行自动换行并保留行尾

#### Scenario: 首次导出 PDF 自动准备浏览器

- **WHEN** 用户提交 PDF 保存，且缺少当前 Playwright 所需的 Chromium
- **THEN** 服务下载匹配的无界面 Chromium 后继续生成 PDF，表单提前提示可能的等待。已有运行时直接复用，安装失败时显示原因和补救方式。其他格式直接导出。

#### Scenario: 使用稳定的本地目录结构

- **WHEN** 文章归档成功或部分成功
- **THEN** 文件保存到 `data/articles/<article-key>/`，并包含可用输出、`metadata.json` 和正文资源；文章目录使用文章 ID 加清理后的标题命名，无法获取 ID 时使用稳定回退名称

#### Scenario: 重复下载保留其他格式

- **WHEN** 用户再次保存同一个文章 URL
- **THEN** 系统更新本次成功生成的格式，保留已有的其他格式及其离线资源；生成失败时先前归档继续可用

#### Scenario: 单项失败保留可用结果

- **WHEN** 单个正文资源下载失败，但所选格式成功生成
- **THEN** 系统保存可用产物并报告缺失资源及原因

#### Scenario: 搜索和浏览已下载文件

- **WHEN** 用户打开首页或输入标题、域名、原始 URL、作者或标签关键词
- **THEN** 列表按最近保存时间倒序展示与关键词和格式条件匹配的文章。选择「全部类型」时，每条记录显示标题和当前可用的全部格式入口，无匹配记录时显示空状态

#### Scenario: 限制本地文件访问

- **WHEN** 用户打开列表中的本地地址
- **THEN** 服务只允许访问 `data/` 下已归档的文件，不暴露任意文件系统路径或暂存目录

#### Scenario: 导出 Markdown

- **WHEN** 用户选择 Markdown 保存单篇文章
- **THEN** 系统生成 UTF-8 的 `article.md`，保留标题、列表、表格、代码块和本地图片路径。结果页和下载记录提供包含 `article.md` 与同级 `assets/` 资源的 ZIP，解压后可离线显示已归档的图片

### Requirement: 兼容和迁移旧版归档

系统 SHALL 将索引和暂存文件存放在 `data/.internal/`，并提供可预览的迁移命令，保留旧版单篇与栏目归档及其访问链接。

#### Scenario: 预览旧版归档迁移

- **WHEN** 用户执行迁移预览
- **THEN** 系统列出源目录和目标目录，磁盘归档保持原状

#### Scenario: 执行旧版归档迁移

- **WHEN** 用户停止服务后明确执行迁移
- **THEN** 系统核对复制结果、更新单篇索引并备份原件，旧文件链接和专题详情仍可访问

### Requirement: 单篇下载文件标注原始 URL

系统 SHALL 在新生成的单篇 HTML、PDF 和 Markdown 正文中显示可点击的原始文章 URL。

#### Scenario: 查看单篇文件的来源

- **WHEN** 用户下载单篇文章并打开生成的 HTML、PDF 或 Markdown 文件
- **THEN** 文件在文章标题下显示提交的文章 URL，保留查询参数，并可通过链接打开原文

#### Scenario: 解压 Markdown 下载包

- **WHEN** 用户打开单篇 Markdown ZIP 中的文档
- **THEN** 文档中显示同一原始文章 URL
